## Предварительный HTTP 405

Установленный PasswordMixin.password_publickeys сам вызывает GET qe/sync
через публичную сессию. Этот метод берёт key ID и публичный RSA-ключ из
заголовков ответа; он не останавливается на 405.

Синтетический HTTP 405 с корректными key headers позволяет зашифровать
пароль и дойти до CAA POST как штатному, так и нашему клиенту. Последующий
синтетический 429 классифицируется как cooldown, без дополнительной отправки.
Поэтому один статус 405 не доказывает поломку шифрования. В реальном задании
CAA POST был отправлен, что согласуется с успешным прохождением шифрования.
Реальные заголовки ответа тогда не сохранялись; причинная связь 405 и 429
по имеющимся данным не установлена.

## Найденный и исправленный дефект

CAA profile-code flow может вызывать challenge_code_or_raised напрямую,
минуя ControlledClient.challenge_resolve. У стандартной библиотеки обработчик
кода использует блокирующий input(), а обработчик смены пароля также запрашивает
stdin. В Celery это может зависнуть или закончиться EOFError.

ControlledClient теперь явно завершает оба callback с challenge_required.
Проверка ручного challenge остаётся в официальном Instagram. Это исправление
устраняет интерактивный запрос в worker; оно не устраняет наблюдавшийся HTTP 429.
