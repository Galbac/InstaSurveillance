# Восстановление подключения через сохранённую сессию

## Когда использовать

Если новый парольный вход получает отказ CAA, можно подключить ранее
сохранённую **мобильную сессию instagrapi того же Instagram-аккаунта**.
Это не создаёт сессию из пароля и не гарантирует, что Instagram примет
старую сессию. Cookie из браузера не считается эквивалентом такого файла.

## Пользовательский сценарий

1. Открыть подключение Instagram и указать username.
2. Выбрать «Сохранённая сессия instagrapi».
3. Выбрать `session.json` размером до 64 КБ и подтвердить условия подключения.
4. Сервис проверяет аккаунт через `account_info()` без парольного входа.
5. Только после совпадения username и Instagram ID сессия сохраняется,
   профиль становится активным и ставится задача первой синхронизации.

Файл получают после ранее успешного входа: `client.dump_settings("session.json")`.
Если такого файла нет, этот способ пока недоступен. Не публикуйте файл,
не добавляйте его в Git и не пересылайте его содержимое в чат.

## Обработка и ограничения

- API принимает либо пароль, либо `session_json`, одновременно оба запрещены.
- Требуются `authorization_data` с sessionid и ds_user_id, UUID устройства
  и device_settings. Входные proxy/password и другие посторонние поля удаляются.
- Используется серверный `INSTAGRAM_PROXY_URL`; маршрут из файла не применяется.
- Содержимое передаётся в зашифрованное временное хранилище с TTL подключения.
- До проверки владельца в БД сохраняются только настройки устройства без токенов.
- После проверки используется штатное зашифрованное хранилище SessionSecret.
- Отклонённая или просроченная сессия не запускает скрытый парольный fallback.
- Наличие действующей сессии не отменяет ограничений Instagram при сборе данных.
- Реальная авторизация этим способом требует действующего файла пользователя;
  тесты с синтетическими сессиями не подтверждают реальный вход.

## Проверки

29 контрактных тестов; две проверки с отдельной PostgreSQL БД подтверждают:
чужой аккаунт отклоняется, парольный login не вызывается, успешная синтетическая
сессия шифруется и временные данные удаляются. Проверки типов backend,
линтеры backend/frontend и TypeScript проходят.
